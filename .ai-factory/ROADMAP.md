# Roadmap проекта

> Поэтапная разработка AI-сервиса на Go + Gin + langchaingo: от диалогов
> и RAG до task pipeline и модерации контента. Реализуется по одной вехе.

## Вехи

- [x] **Bootstrap проекта** — скелет Gin-приложения (`go mod`,
  `cmd/api/main.go`, `internal/infrastructure/config` на env),
  docker-compose (app + PostgreSQL + Redis + Qdrant), структурированное
  логирование (`log/slog`, уровень через `LOG_LEVEL`), `/health`-эндпоинт.
- [x] **Фундамент работы с БД** — GORM (`*gorm.DB`, пул соединений,
  хелпер транзакций), golang-migrate миграции, первый модуль (`dialog`)
  со сквозным CRUD через repository-паттерн — база для остальных модулей.
- [ ] **Диалоги с LLM (базовый чат)** — модели `Dialog`/`DialogMessage`,
  интеграция с langchaingo chat-моделью (OpenAI), эндпоинт отправки
  сообщения с сохранением истории в PostgreSQL.
- [ ] **Tool calling у LLM (structured output)** — модель не просто
  генерирует текст, а вызывает инструменты-функции; параметры и
  результат вызова описаны Go-структурами и JSON Schema. Базовый
  паттерн на простом примере — переиспользуется в следующих вехах для
  получения данных (БД, RAG-поиск, внешние API) и других фич.
- [ ] **Диалог как state machine** — перевод логики диалога на явную
  машину состояний (состояние разговора, переходы, вызов инструментов
  из шагов) вместо линейного вызова LLM.
- [ ] **Работа с файлами** — приём файлов, S3-совместимое хранилище
  (MinIO), парсинг PDF/DOCX/XLSX в текст.
- [ ] **RAG: индексация статей** — чанкинг текста, генерация embeddings
  (langchaingo), upsert в Qdrant.
- [ ] **RAG: поиск и ответ с источниками** — retriever + rerank +
  формирование ответа LLM со ссылками на источники, интеграция с
  диалогом.
- [ ] **Task pipeline как state machine** — модели `Task`/`TaskStep`/
  `TaskResult`, конвейер как машина состояний.
- [ ] **Фоновые задачи и колбэки** — asynq-воркер (`cmd/worker`), вынос
  RAG-индексации и обработки задач в фон, колбэк о результате.
- [ ] **Модерация контента (первый конвейер)** — один вид модерации
  (например, сообщения) как LLM-классификация с кодами ошибок, поверх
  паттерна task pipeline.
- [ ] **Остальные конвейеры модерации** — модерация профиля, аватара,
  файлов профиля, проектов, "хочу"-заявки — по образцу первого
  конвейера.
- [ ] **API-ключи и контексты доступа** — разграничение доступа
  внешних клиентов по ключам/контекстам через Gin middleware.
- [ ] **Устойчивость и наблюдаемость** — единый формат ошибок API
  (`application/problem+json`), тестовое покрытие ключевых модулей,
  финальная полировка логирования.
