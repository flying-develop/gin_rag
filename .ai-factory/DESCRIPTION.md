# AI Service

## Обзор

AI-сервис на Go: диалоги с LLM, RAG по статьям, конвейер обработки
задач и модерация пользовательского контента. Сервис предоставляет
HTTP API для внешних клиентов и выполняет тяжёлые операции (индексация,
классификация, обработка файлов) в фоновых воркерах.

Разработка ведётся поэтапно — от минимального сквозного сценария
(один диалог с LLM, сохранение истории в БД) к более сложным
(RAG, task pipeline, несколько конвейеров модерации). Порядок этапов —
в `.ai-factory/ROADMAP.md`.

## Ключевые возможности

- **Диалоги с LLM** — чат-сессии (`Dialog`/`DialogMessage`), пошаговые
  ответы ассистента с сохранением истории.
- **Tool calling у LLM** — модель вызывает инструменты-функции
  (structured output); параметры и результат описаны Go-структурами и
  JSON Schema, а не парсятся из свободного текста. Сквозной паттерн:
  используется для получения данных (запросы к БД, RAG-поиск, вызовы
  внешних API) и реализации фич поверх langchaingo.
- **RAG по статьям** — индексация статей (chunking → embedding →
  upsert в векторную БД), поиск релевантных чанков, rerank,
  формирование ответа с источниками.
- **Обработка задач (Task pipeline)** — асинхронный конвейер с
  состояниями и шагами (`Task` → `TaskStep` → `TaskResult`) с ретраями
  и колбэками о результате.
- **Модерация контента** — независимые конвейеры модерации (профиль,
  аватар, обложка профиля, файлы профиля, сообщения, "хочу"-заявки) на
  базе LLM-классификации с кодами ошибок.
- **Работа с файлами** — приём, парсинг (PDF/DOCX/XLSX → текст),
  хранение (S3-совместимое хранилище).
- **API-ключи и контексты доступа** — разграничение доступа внешних
  клиентов по ключам и контекстам.

## Технологический стек

| Слой | Технология |
|------|-----------|
| Язык / рантайм | Go 1.23+ |
| HTTP-фреймворк | Gin (`github.com/gin-gonic/gin`) |
| Валидация входа | binding-теги + `go-playground/validator` |
| ORM | GORM (`gorm.io/gorm`, `gorm.io/driver/postgres`) |
| Слой доступа к БД | repository-структуры поверх GORM |
| Миграции | golang-migrate (`github.com/golang-migrate/migrate`), SQL up/down |
| База данных | PostgreSQL |
| Фоновые задачи / очереди | asynq (`github.com/hibiken/asynq`) + Redis |
| AI-оркестрация | langchaingo (`github.com/tmc/langchaingo`) |
| Конвейеры состояний | явные state machine в сервисном слое |
| LLM-провайдер | OpenAI через `llms.Model` (сменяемый интерфейс) |
| Векторная БД | Qdrant (`langchaingo/vectorstores/qdrant`) |
| Конфигурация | env через `caarlos0/env` + `joho/godotenv` |
| Логирование | `log/slog`, уровень через `LOG_LEVEL` |
| Тесты | `testing` + `stretchr/testify`, реальный Postgres из Docker |
| Зависимости | Go modules |
| Окружение разработки | Docker / docker compose |

Примечания:

- **`context.Context`** — сквозной параметр для таймаутов и отмены
  длинных операций (БД, LLM, HTTP); передаётся первым аргументом во все
  методы сервисов и репозиториев.
- **LLM-провайдер** конфигурируется через `.env` и скрыт за интерфейсом
  `llms.Model` — добавление Anthropic/Gemini/Qwen не требует изменения
  вызывающего кода.
- **DI без контейнера:** зависимости собираются вручную в
  `cmd/*/main.go` и передаются через конструкторы
  (`NewDialogService(repo, llm)`) — идиоматично для Go.

## Архитектура

Подробные гайдлайны — в `.ai-factory/ARCHITECTURE.md`.
Паттерн: **Structured Modules (Technical Layer)**.

- Каждый домен (диалоги, RAG, task pipeline, модерация, файлы) —
  отдельный модуль в `internal/modules/<module>/` со своими
  `handler/service/repository/model/dto`.
- Внутри модуля — строгий поток `handler → service → repository`,
  прямого доступа к БД из сервисов или хендлеров быть не должно.
- Конвейеры модерации и RAG-обработка реализуются как явные state
  machine (состояние + переходы).
- Сквозная инфраструктура (БД, Redis, Qdrant, LLM-клиенты, конфиг,
  логирование, HTTP-сервер) — в `internal/infrastructure/`, без
  бизнес-логики.
- Конфигурация провайдеров (LLM, embeddings, БД, Redis, Qdrant, S3)
  — через переменные окружения (`.env`).

## Нефункциональные требования

- **Логирование:** структурированное (`log/slog`), уровень
  настраивается через `LOG_LEVEL`.
- **Обработка ошибок:** единый формат ошибок API
  (`application/problem+json`), явные коды доменных сбоев (модерация,
  RAG, PII) через типизированные ошибки Go.
- **Безопасность:** секреты и API-ключи только через переменные
  окружения, не коммитятся в репозиторий; валидация входных данных на
  границе API.
- **Конкурентность:** I/O-операции (БД, LLM, Redis, Qdrant, S3) —
  через `context.Context` с таймаутами и отменой; долгие операции — в
  asynq, а не в HTTP-обработчиках.
- **Окружение разработки:** локально всё поднимается через Docker /
  docker compose (сервис на Gin, PostgreSQL, Redis, Qdrant) — без
  установки зависимостей и БД напрямую на хост-машину. Конфигурация
  Docker создаётся отдельным этапом через `/aif-dockerize`.
